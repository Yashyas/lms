Dual-Channel Architecture Live in Backend ACTIVE & HARDENED

The LMS payment system uses a dual-channel fulfillment architecture. The client redirect verification provides instant UI feedback with zero latency, while the Stripe webhook listener operates as an asynchronous, authoritative safety net for network drops, tab closures, and automated refund revocations.

Dual-Channel Checkout & Fulfillment Flow

End-to-End Sequence
01
Student clicks "Enroll / Buy Course"
Frontend sends POST /payments/checkout/:courseId with the user's Better-Auth session cookie or Bearer token. (Guarded: Rate limited to 5/min).
02
Backend Pre-Validation & Checkout Session Initialization
PaymentsService.createCheckoutSession authoritatively validates:
  • Course exists and published: true (cannot buy unpublished drafts)
  • Instructor ownership check (instructors cannot purchase their own courses)
  • Price validation (paid courses only: price > 0; free courses use direct enrollment)
  • Duplicate enrollment check (throws 409 Conflict if student is already enrolled)
Creates a Postgres record in payment with status: PENDING, calls Stripe API, stores stripeSessionId, and returns { url, sessionId }.
03
Hosted Stripe Checkout & Card Processing
Student is redirected to Stripe's hosted checkout. Metadata (paymentId, courseId, userId) is embedded in both the session and payment intent.
04
Channel A: Immediate Client Redirect Verification (Zero UI Delay)
Browser redirects back to /payment-success?sessionId={CHECKOUT_SESSION_ID}. The frontend immediately calls POST /payments/verify-session { sessionId }. Backend queries Stripe, validates payment_status === 'paid', and executes fulfillOrder() in an atomic transaction: updates Payment to COMPLETED and inserts the Enrollment record.
05
Channel B: Asynchronous Authoritative Webhook Sync (Safety Net)
Stripe sends checkout.session.completed or checkout.session.async_payment_succeeded to POST /payments/webhook. Verified via raw-body signature matching. fulfillOrder() runs idempotently — if Channel A already enrolled the user, it cleanly detects the existing record and safely skips duplicate creation.
06
Channel C: Refund & Automatic Enrollment Revocation
When an administrator issues a refund via POST /payments/refund/:paymentId or directly inside the Stripe Dashboard, Stripe emits charge.refunded. Backend's revokeEnrollment() finds the associated Enrollment, removes student access, and flips payment status to REFUNDED.

Fulfillment Comparison: Redirect vs. Webhooks

Feature Channel A: Client Redirect Verification Channel B: Stripe Webhook Listener
Primary Purpose Instant student access & immediate celebratory screen Authoritative background reconciliation & async payments
Endpoint POST /payments/verify-session POST /payments/webhook
Authorization Authenticated Student Session (Rate limited: 15/min) Anonymous with stripe-signature HMAC verification
Failure Resilience Vulnerable if user closes tab immediately 100% resilient; Stripe retries with exponential backoff
Async Payment Support Holds enrollment if payment status is pending Enrolls student when async_payment_succeeded fires
Refund Handling N/A Automated revocation via charge.refunded

PaymentsController REST Specification

6 Endpoints Live

All endpoints are fully implemented in backend/src/payments/payments.controller.ts and wired to PaymentsService with NestJS guards and Throttler rate limits.

POST /payments/checkout/:courseId
Throttle: 5/min | Authenticated Student

Validates course price & eligibility, creates a PENDING Payment record, and generates a Stripe Checkout Session with product thumbnail and line items. 

// Response (201 Created)
{
  "url": "https://checkout.stripe.com/c/pay/cs_test_a1b2c3...",
  "sessionId": "cs_test_a1b2c3..."
}
POST /payments/verify-session
Throttle: 15/min | Authenticated Student

Called on client redirect. Retrieves session from Stripe, validates student ownership, calls atomic fulfillOrder(), and unlocks curriculum. 

// Request Body
{ "sessionId": "cs_test_a1b2c3..." }

// Response (200 OK)
{
  "message": "Payment verified and enrolled successfully",
  "payment": { "id": "cm3...", "status": "COMPLETED", "price": 4900 },
  "courseSlug": "nestjs-advanced-masterclass"
}
GET /payments/my-history
Authenticated Student

Returns all receipts and transaction records for the logged-in student with course title, price paid, status, and enrollment timestamps.

GET /payments/course/:courseId
Instructor / Admin Only

Allows course author or platform administrator to audit sales, customer emails, and payment statuses for a specific course.

POST /payments/refund/:paymentId
Admin Only | Throttle: 10/min

Issues a direct Stripe refund via stripe.refunds.create({ payment_intent }) and immediately triggers revokeEnrollment() inside an atomic database transaction.

POST /payments/webhook
@AllowAnonymous() | @SkipThrottle()

Consumes unparsed binary req.rawBody, verifies HMAC signature against STRIPE_WEBHOOK_SECRET, and dispatches to handler switchboard.

Production schema.zmodel Definition

Applied via ZenStack

The Payment model in packages/db/zenstack/schema.zmodel includes strict status enums, onDelete: SetNull constraints, snapshot fields, and Row-Level Security: 

enum PaymentStatus {
    PENDING
    COMPLETED
    FAILED
    REFUNDED
}

model Payment {
    id                    String          @id @default(cuid())
    userId                String?         
    user                  User?           @relation(fields: [userId], references: [id], onDelete: SetNull)
    
    courseId              String?
    course                Course?         @relation(fields: [courseId], references: [id], onDelete: SetNull)
    
    enrollmentId          String?         @unique
    enrollment            Enrollment?     @relation(fields: [enrollmentId], references: [id], onDelete: SetNull)

    userEmail             String          // Snapshot: email of user buying course
    courseTitle           String          // Snapshot: course title at time of purchase

    price                 Int             // stored in cents/paise
    currency              String          @default("usd")
    status                PaymentStatus   @default(PENDING)
    provider              String          @default("stripe")
    stripeSessionId       String?         @unique
    stripePaymentIntentId String?         @unique
   
    createdAt             DateTime        @default(now())
    updatedAt             DateTime        @updatedAt
   
    // ZenStack Row-Level Security
    @@allow('read', (userId != null && auth().id == userId) || (course != null && course.instructorId == auth().id) || auth().role == 'admin')
    @@allow('all', auth().role == 'admin')
    
    @@index([userId])
    @@index([courseId])
    @@index([stripeSessionId])
   
    @@map('payment')
}

Key Architectural Decisions:

  • Audit Trail Integrity (onDelete: SetNull): If a student or course is deleted, financial transaction records are preserved for accounting and tax compliance, backed by snapshot fields (userEmail, courseTitle).
  • Row-Level Security (RLS): Students can only view their own receipts. Course instructors can only see payments for their own authored courses. Admins have global access.
  • Unique Indexes: stripeSessionId and stripePaymentIntentId are strictly unique, guaranteeing zero double-processing.

Webhook Switchboard & Event Matrix

6 Handled Events

The webhook handler in payments.controller.ts processes synchronous and asynchronous lifecycle events with automated database sync:

Stripe Event Type Trigger Condition Backend Action
checkout.session.completed Card successfully charged in hosted checkout Calls fulfillOrder(): creates Enrollment & sets status COMPLETED
checkout.session.async_payment_succeeded Delayed payment methods (ACH, SEPA, Boleto) clear Calls fulfillOrder() to enroll student asynchronously
checkout.session.expired Student leaves checkout tab open for 24+ hours Calls markpaymentFailed(): sets status FAILED
payment_intent.payment_failed Card declined or insufficient funds Calls markpaymentFailed() with error reason logged
checkout.session.async_payment_failed Delayed payment voucher or bank transfer bounces Calls markpaymentFailed(): prevents unearned enrollment
charge.refunded Refund issued in Stripe dashboard or via Admin API Calls revokeEnrollment(): deletes Enrollment & sets status REFUNDED

Pre-Deployment Security Checklist:

  • Cloudflare WAF Bypass: Create a Cloudflare WAF rule to bypass Bot Fight Mode and Managed Challenges for /payments/webhook so Stripe IPs are never blocked.
  • Raw Body Preservation: main.ts specifies bodyParser: false, rawBody: true so Express preserves the unaltered binary Buffer required for Stripe HMAC validation.
  • Rate Limit Exemption: @SkipThrottle() is applied to /payments/webhook to avoid 429 errors during Stripe bulk test simulations or batch retries.
