End-to-End System Architecture

Industry Standard

Mirrors production media platforms (Udemy, Coursera): large media uploads never touch or bottleneck the NestJS API server, compute-heavy transcoding runs in a sandboxed background queue, and playback is cryptographically secured via HLS AES-128 ClearKey encryption.

01. INGESTION
Direct-to-S3 Upload
Instructors stream multi-GB raw MP4s directly into Garage S3 using presigned PUT URLs, bypassing NestJS memory limits.
02. ORCHESTRATION
BullMQ + Redis Worker
Decoupled queue worker executes CPU-intensive FFmpeg jobs asynchronously with retry, progress reporting, and cleanup.
03. DRM / SECURITY
HLS AES-128 Encryptor
FFmpeg slices videos into 6-second chunks encrypted with unique 16-byte cryptographic keys and IVs for each lesson.
04. GATED STREAMING
Key Delivery Server
Player requests decryption keys from NestJS, which verifies user authentication and course enrollment via ZenStack policies.
Why AES-128 HLS Over Direct MP4 Streaming?
Plain MP4 links can be ripped in 1-click and cannot adapt to changing student bandwidth. Multi-bitrate HLS dynamically switches resolutions (1080p, 720p, 480p, 360p) based on network speed. AES-128 encrypts every .ts segment so intercepted chunks cannot be played without reaching your authenticated key endpoint.

Complete Request & Processing Lifecycle

6 Stages
1
Presigned Upload Request
Instructor frontend calls POST /video-asset/upload-url. NestJS validates instructor ownership and returns a signed Garage S3 PUT URL for raw-videos/{lessonId}/{uuid}.mp4.
2
Direct Client-to-Garage Upload
Browser streams raw MP4 directly to Garage S3 with a progress bar. Once finished, client notifies NestJS via PATCH /video-asset/:lessonId/upload-complete.
3
BullMQ Job Dispatch & Status Transition
NestJS verifies file existence in S3, updates video status to PROCESSING, and enqueues a job into Redis: { videoAssetId, lessonId, rawStorageKey }.
4
FFmpeg Transcoding, Segmenting & AES-128 Encryption
Worker pulls job, downloads raw video to temp directory, probes dimensions, creates 16-byte random key & IV, runs FFmpeg to generate adaptive ABR streams (1080p, 720p, 480p, 360p) + master.m3u8 + encrypted .ts chunks, and streams them into hls/{lessonId}/ in Garage S3.
5
Secure Playback & Key Gating
Enrolled student opens lesson. The video player fetches master.m3u8. When reaching #EXT-X-KEY:METHOD=AES-128,URI="/api/videos/:id/key", the browser requests the key. NestJS verifies enrollment via ZenStack and returns the raw 16-byte binary key with no-store headers.
6
Heartbeat Progress Tracking & Auto-Completion
During playback, the player emits throttled heartbeats to POST /lesson-progress/heartbeat/:lessonId. When student reaches $\ge 90\%$ duration, the lesson is automatically marked as completed: true.

1.4 Secure AES-128 Key Delivery Endpoint

Implemented

When an HLS player reads #EXT-X-KEY:METHOD=AES-128,URI="...", it requests the key. The endpoint returns the raw 16-byte binary buffer under strict authorization checks. 

// GET /api/videos/:lessonId/key or /videos/:lessonId/key
@Get(':lessonId/key')
@AllowAnonymous()
async getKey(
  @Param('lessonId') lessonId: string,
  @Session() session: UserSession | undefined,
  @Res() res: Response,
) {
  // Authoritatively verifies:
  // 1. If lesson is marked isFree -> allow access
  // 2. If student is enrolled in the parent course -> allow access
  // 3. If user is course instructor or admin -> allow access
  const keyBuffer = await this.videoAssetService.getVideoKey(lessonId, session?.user);

  res.setHeader('Content-Type', 'application/octet-stream');
  res.setHeader('Cache-Control', 'no-store, no-cache, must-revalidate, private');
  res.setHeader('Content-Length', keyBuffer.length);
  return res.end(keyBuffer);
}

2.1 Heartbeat Playback Tracking Engine

Implemented

While a student watches a lesson, the frontend player emits a throttled heartbeat ping. Implemented in backend/src/lesson-progress/lesson-progress.service.ts: 

// POST /lesson-progress/heartbeat/:lessonId
// Request Body: { lastPlayedSecond: 145, duration: 600 }

async recordHeartbeat(recordHeartbeatDto: RecordHeartbeatDto, user: AuthUser, lessonId: string) {
  const lesson = await this.db.forUser(user).lesson.findUnique({
    where: { id: lessonId },
    select: { id: true, courseId: true },
  });

  if (!lesson) {
    throw new NotFoundException('Lesson not found or you are not enrolled');
  }

  // Check 90% completion threshold
  const COMPLETION_THRESHOLD = 0.90;
  const shouldMarkCompleted =
    recordHeartbeatDto.duration > 0 &&
    recordHeartbeatDto.lastPlayedSecond / recordHeartbeatDto.duration >= COMPLETION_THRESHOLD;

  // Upsert progress (never un-complete an already completed lesson)
  return await this.db.forUser(user).lessonProgress.upsert({
    where: { userId_lessonId: { userId: user.id, lessonId } },
    create: {
      userId: user.id,
      lessonId,
      lastPlayedSeconds: Math.floor(recordHeartbeatDto.lastPlayedSecond),
      completed: shouldMarkCompleted,
      completedAt: shouldMarkCompleted ? new Date() : null,
    },
    update: {
      lastPlayedSeconds: Math.floor(recordHeartbeatDto.lastPlayedSecond),
      ...(shouldMarkCompleted ? { completed: true, completedAt: new Date() } : {}),
    },
  });
}

2.2 Course Completion & Progress Aggregation

Implemented

Calculates overall completion percentage and determines the next unwatched lesson for a seamless "Continue Learning" UX. 

// GET /lesson-progress/course/:courseId/progress
async getCourseProgress(courseId: string, user: AuthUser) {
  const lessons = await this.db.forUser(user).lesson.findMany({
    where: { courseId },
    orderBy: { position: 'asc' },
    select: { id: true, position: true },
  });

  const progress = await this.db.forUser(user).lessonProgress.findMany({
    where: {
      lessonId: { in: lessons.map(l => l.id) },
      completed: true,
    },
    select: { lessonId: true },
  });

  const completedLessonIds = new Set(progress.map(p => p.lessonId));
  const total = lessons.length;
  const completed = progress.length;
  const percentage = total > 0 ? Math.round((completed / total) * 100) : 0;
  const nextLesson = lessons.find(l => !completedLessonIds.has(l.id)) || lessons[0];

  return {
    courseId,
    completedLessons: progress.map(p => p.lessonId),
    totalLessons: total,
    percentage,
    nextLessonId: nextLesson?.id ?? null,
  };
}

2.3 Frontend Player Setup (Hls.js + Cookie Auth)

Frontend Spec

Next.js integration snippet using hls.js. It enables cookies so the AES-128 key request is authenticated and sends heartbeats. 

import Hls from 'hls.js';
import { useEffect, useRef } from 'react';

export function LessonVideoPlayer({ masterPlaylistUrl, lessonId, initialTime = 0 }) {
  const videoRef = useRef<HTMLVideoElement>(null);

  useEffect(() => {
    const video = videoRef.current;
    if (!video) return;

    if (Hls.isSupported()) {
      const hls = new Hls({
        // Sends session cookies with .m3u8, .ts, and /key requests
        xhrSetup: (xhr) => {
          xhr.withCredentials = true; 
        }
      });

      hls.loadSource(masterPlaylistUrl);
      hls.attachMedia(video);

      hls.on(Hls.Events.MANIFEST_PARSED, () => {
        if (initialTime > 0) video.currentTime = initialTime;
      });

      // Heartbeat every 30-60 seconds
      let lastPing = 0;
      const onTimeUpdate = () => {
        const now = Math.floor(video.currentTime);
        if (now - lastPing >= 30 && video.duration) {
          lastPing = now;
          fetch(`/lesson-progress/heartbeat/${lessonId}`, {
            method: 'POST',
            credentials: 'include',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ lastPlayedSecond: now, duration: Math.floor(video.duration) })
          });
        }
      };

      video.addEventListener('timeupdate', onTimeUpdate);
      return () => {
        video.removeEventListener('timeupdate', onTimeUpdate);
        hls.destroy();
      };
    }
  }, [masterPlaylistUrl, lessonId, initialTime]);

  return <video ref={videoRef} controls className="w-full rounded-lg bg-black aspect-video" />;
}

Production schema.zmodel Definition

Applied via ZenStack

The exact models and relations currently deployed in packages/db/zenstack/schema.zmodel: 

enum VideoStatus {
    PENDING_UPLOAD
    PROCESSING
    READY
    FAILED
}

model VideoAsset {
    id                  String          @id @default(cuid())
    status              VideoStatus     @default(PENDING_UPLOAD)
    lessonId            String          @unique
    lesson              Lesson          @relation(fields: [lessonId], references: [id], onDelete: Cascade)
    rawStorageKey       String?
    hlsMasterUrl        String?
    durationSeconds     Int             @default(0)
    encryptionKey       String?         // 16-byte AES key (hex)
    encryptionIv        String?         // 16-byte IV (hex)
    errorMessage        String?
    createdAt           DateTime        @default(now())
    updatedAt           DateTime        @updatedAt

    // Encryption key is protected from public/student queries
    @@allow('all', auth().id == lesson.course.instructorId || auth().role == 'admin')
    @@map('video_asset')
}

model LessonProgress {
    id                  String      @id @default(cuid())
    userId              String      @default(auth().id)
    user                User        @relation(fields: [userId], references: [id], onDelete: Cascade)
    lessonId            String
    lesson              Lesson      @relation(fields: [lessonId], references: [id], onDelete: Cascade)
    lastPlayedSeconds   Int         @default(0)
    completed           Boolean     @default(false)
    completedAt         DateTime?   
    createdAt           DateTime    @default(now())
    updatedAt           DateTime    @updatedAt

    // ZenStack RLS: Student owns progress; instructor has read visibility
    @@allow('read,create,update', auth().id == userId || auth().role == 'admin')
    @@allow('read', lesson.course.instructorId == auth().id)

    @@unique([userId, lessonId])
    @@map('lesson_progress')
}
